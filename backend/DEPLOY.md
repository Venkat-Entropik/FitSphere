# Deploying the FitSphere backend (free, no card)

The backend is one container (Fastify). Your data lives in **PostgreSQL**, so the container itself keeps
nothing and can be restarted or replaced freely.

- **Database:** Neon (free plan, no credit card). 1 GB.
- **Backend:** Render's free web service. It sleeps after about 15 minutes without traffic and takes about a
  minute to wake on the next request. Your data is safe while it sleeps.

## 1. Create the database (Neon)

1. Sign up at neon.com (GitHub or email), then **Create project** (any name, any region close to you).
2. On the project dashboard click **Connect** and copy the **connection string**. It starts with
   `postgresql://` and ends with `?sslmode=require`. Keep it secret; it is a password.

## 2. Create the backend (Render)

1. Push the repo to GitHub and sign up at render.com (GitHub login is simplest).
2. **New → Blueprint** → pick the `FitSphere` repo. Render reads `render.yaml` (free plan, no disk).
3. When prompted:
   - `DATABASE_URL`: paste the Neon connection string.
   - `GEMINI_API_KEY`, `RESEND_API_KEY`, `MAIL_FROM`: leave blank for now (see the table below).
   - `JWT_SECRET` is generated for you.
4. **Apply**. The first build takes a few minutes. Your URL is `https://fitsphere-backend-xxxx.onrender.com`.

The free plan should not ask for a card. If Render asks for one anyway, any other Docker host works with the same variables.

## Variables

| Variable                         | Value                                                                                                                             |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                   | Required. The Neon connection string. The server refuses to start in production without it.                                       |
| `JWT_SECRET`                     | Required. Generated by the blueprint. Otherwise: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` |
| `TRUST_PROXY`                    | `true` behind Render (set by the blueprint), so rate limits see each client's real IP.                                            |
| `CORS_ORIGINS`                   | Only if you serve the app on the web: your web origin, e.g. `https://app.example.com`. Native apps ignore CORS.                   |
| `RESEND_API_KEY`, `MAIL_FROM`    | Needed for password-reset emails (resend.com, with a verified sending domain). Without them no email is sent.                     |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Optional. Without a key the coach uses built-in rule-based answers. Never put this in the app.                                    |

Do not set `PORT` or `HOST`; the platform and Dockerfile handle them.

## 3. Check it works

```bash
curl https://<your-domain>/health          # {"status":"ok"}  (the first call after a sleep takes ~1 minute)
curl -i https://<your-domain>/profile      # 401, not 404
```

Register an account from the app, wait 20 minutes for the service to sleep, then sign in again. The account
should still be there (it lives in Neon).

## 4. Point the app at it

At build time (EAS build profile `env`, or `.env` for a local build):

```
EXPO_PUBLIC_API_URL=https://<your-domain>
EXPO_PUBLIC_USE_MOCKS=false
```

These values are bundled into the app, so never put secrets here.

## Free-tier limits to know about

- **Cold starts:** the first request after a pause is slow. The app shows its loading state meanwhile.
- **Instance hours:** Render's free plan has a monthly limit of running hours; a sleeping service uses none.
- **Neon:** 1 GB of storage on the free plan; writes fail (nothing is deleted) if you pass it.
- **Rate limits are in memory** and reset when the service restarts. Keep a single instance.

## Before real users

- **Back up the database.** Neon keeps short-term history on the free plan; export with `pg_dump` for more.
- **Test the reset email** once with your real `RESEND_API_KEY`: use Forgot password in the app and check that
  the code arrives (and isn't in spam).
- **Logs:** view them in Render. They show method, path, status and errors only; request bodies, headers,
  tokens and passwords are never logged.

## Other hosts

The same Dockerfile runs on Railway, Fly.io and others. Set the same variables. With a paid host you can keep
the data on the host's own Postgres instead of Neon.
